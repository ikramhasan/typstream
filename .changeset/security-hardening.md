Security hardening (#29). The engine client has limits (`createEngine({ limits })`, `DEFAULT_LIMITS`). Input longer than `maxLength` (1 MiB of UTF-16 code units) isn't healed or compiled: the document fails with the new reason `too-large`, keeps its last artifact, and rejects exports (`ExportError` reason `too-large`) until `set()` or `reset()` brings it under the limit. A streaming paged compile with more than `livePages` (100) pages stops live compiling (`too-complex`); `finish()` compiles every page. The worker now ends, and the client replaces it, when wasm overflows the host's stack (content nested too deep), which browsers throw as `RangeError` or `InternalError` rather than a wasm trap; it used to answer `internal` and keep using the broken instance. The HTML renderer applies the inline styles of Typst's HTML through the CSSOM instead of parsing `style` attributes, so pages with a strict Content-Security-Policy (`style-src` without `'unsafe-inline'`) keep html-compat's layout in Chromium and Firefox, without a violation report per element. The website's security guide (`/docs/guides/security`) has the threat model and the policy to serve typstream under.
