`@typstream/engine` compiles streamed Typst in a worker. It has two halves:

- **The client** (`@typstream/engine`), on the main thread. It heals each document with
  [`@typstream/heal`](/docs/reference/heal), decides when to compile, and keeps the preview alive when compiles fail,
  hang or crash. You open a document, feed it text, and subscribe to its state.
- **The server** (`@typstream/engine/server`), in the worker. It runs Typst 0.15.1
  ([`@typstream/engine-wasm`](/docs/reference/engine-wasm)) behind the protocol in
  [`@typstream/core`](/docs/reference/core#protocol), fixes errors a stream causes, and falls back to something
  showable when a document still doesn't compile.

`@typstream/engine/worker` is the default worker script that joins the two; `engineWorker()` spawns it.
`@typstream/engine/websocket` connects the client to a server instead: [`fromWebSocket`](#typstreamenginewebsocket).

## When to use it

Use the engine directly when you render the artifacts yourself, run your own worker, or share one engine across
several roots. To show documents in the page, [`@typstream/dom`](/docs/reference/dom)'s `mountTypstream` and the
React bindings ([`typstream`](/docs/reference/typstream), [`@typstream/react`](/docs/reference/react)) drive an engine
for you. On a server, use [`@typstream/node`](/docs/reference/node).

## Install

```npm
npm install @typstream/engine
```

The default worker loads the wasm and the base fonts as assets next to its own script. Vite and Next.js (Turbopack or
webpack) need no configuration. The wasm is about 19 MB (about 6 MB with brotli) and the fonts 2.6 MB: serve them
compressed and cacheable. See [Self-hosting the engine](/docs/guides/self-hosting) to load them from elsewhere.

## Example

```ts
import { createEngine, engineWorker } from "@typstream/engine";

const engine = createEngine({ spawn: engineWorker() });
const doc = engine.open({ target: "html" }); // or "paged": pages as SVG, or drawings with pageFormat: "drawing"

doc.subscribe(({ status, artifact, diagnostics }) => render(artifact, status, diagnostics));
for await (const chunk of llmStream) doc.push(chunk);
doc.finish(); // strict heal, final compile → status "done" or "error"
```

`state.artifact` is `{ target: "html", html }` or `{ target: "paged", pageCount, pages }`. Hand it to
[`createHtmlRenderer`](/docs/reference/dom#createhtmlrenderer) or [`createPagedView`](/docs/reference/dom#createpagedview)
rather than inserting it yourself: Typst's HTML is untrusted and needs sanitizing.

## What the client does

- **Heals on the main thread.** Every `push`, `set` and `applyEdit` runs the incremental healer. A change that heals to
  the same source doesn't compile.
- **Latest wins.** The engine runs one compile at a time across all its documents. Each document has at most one
  compile pending, and it reads the newest healed source when its turn comes. Edits reach the worker as one diff right
  before the compile.
- **Adaptive interval.** Compiles start at most every `clamp(minInterval, 1.25 × average compile time, maxInterval)`
  (33 to 500 ms by default). When a line or block has just finished (heal's `stableOffset` advanced), the next compile
  is due after `minInterval` instead.
- **Stale output is dropped.** Diagnostics and artifacts count only for the revision last sent. Diagnostics are mapped
  back to input positions (UTF-16 offsets into the text you pushed).
- **Last good.** A failed compile keeps the previous artifact. While streaming the status is `stale`; in final mode it
  is `error`. Before it comes to that, the worker's fixers and fallback usually find something to show.
- **Watchdog.** Each compile gets 3 s while streaming and 10 s in final mode. Past that, the worker is terminated and
  an initialized spare takes over. After 3 timeouts or crashes, live compiling stops (`failure.reason` is
  `"too-complex"`); `finish()` still compiles once.
- **Recycling.** A worker that reports more than 256 MiB after a compile is swapped for the spare between compiles.
- **Limits.** Input longer than `maxLength` (1 MiB of UTF-16 code units) isn't healed or compiled: the document
  reports `too-large` and keeps its last artifact until `set()` or `reset()` brings it back under the limit. A
  streaming paged compile with more than `livePages` (100) pages stops live compiling; `finish()` compiles every page.
- **Paged output.** The worker sends changed pages only; the client merges them, so `state.artifact` always has every
  page.

A document's status goes `idle` → `compiling` → `idle` while streaming, `stale` after a failed compile, and `done` or
`error` once finished. Everything runs on injected timers (`clock`), so the client also works in Node.

[The engine](/docs/concepts/engine) explains the design behind these rules.

## Fixers and fallback

When a compile fails, the server tries its diagnostic fixers and recompiles, at most twice per revision, so streamed
text that heals but doesn't compile yet still renders:

| Fixer | What it does |
| --- | --- |
| `tail-cut` | Streaming only. An error in the text still being typed (after heal's `stableOffset`) cuts the text there and heals the rest again. `#text(` without its body, `#v(1`, `rgb("#e` and closure parameters before `=>` drop out until the next tokens bring them back. |
| `pending-ref` | A reference to a label that doesn't exist yet (a citation before `#bibliography`) shows its key as a muted placeholder. In final mode the error is still reported. |
| `package-stub` | An import of a package the document can't have (not allowed, still loading, failed to load) binds the names it imports to placeholders showing the package's spec. Wildcard imports and modules whose fields are used can't be stood in for. |
| `missing-image` | An image the document has no file for shows as a placeholder with the file's name, keeping the call's size and alt text and a figure's caption. String paths are replaced before the first compile, all at once; the fixer handles paths in variables, and files whose extension names another format. In final mode the error is still reported. See [Images](/docs/guides/images). |
| `hoist-import` | A name used before the package import that binds it (a helper on CeTZ above `#import "@preview/cetz:0.5.3"`, `#unit(…)` in a template's arguments above unify's import) moves that import to the document's start. Only an import that binds the name outright (bare, `as`, items) at the top level; not a wildcard. While streaming, only a settled import. In final mode the error is still reported. |

Fixed errors are reported as `info` diagnostics while streaming, with the fixer's name as `source`. Plugins add
fixers as ES modules loaded in the worker; see [Writing a plugin](/docs/guides/writing-a-plugin).

What still fails after the fixers is never a blank screen. The server shows failing top-level blocks as "This part
couldn't be displayed" boxes, shows the unsettled tail as plain text once the last good render is 1.5 s old, and in
final mode the client finds and skips blocks that hang or crash the engine. `state.lastCompile.fallback` says what was
isolated. `fallback: false` on a document turns this off. [Fallback](/docs/concepts/fallback) has the whole ladder.

## Events

The library sends nothing anywhere: it reports, and the app decides what to collect. `doc.onEvent(listener)` hears
one document. `engine.onEvent(listener)` hears the workers and, as `{ type: "document", event }`, every document's
events too. A compile reports, in this order and before the state it leads to is published:

| Event | When |
| --- | --- |
| `diagnostics` | The worker reported diagnostics (with every compile, and when it recompiles on its own). |
| `compiled` | A compile finished, with its timings, heal time and patches, the fixers applied and the fallback level. |
| `fallback` | The output isn't the text as it is (levels 1 to 4), with the input and healed source to replay as a test case. |
| `watchdog` | A compile ran past its budget or crashed the worker. |

The event shapes are in [`@typstream/core`](/docs/reference/core#telemetry-events). See
[Telemetry](/docs/guides/telemetry).

## Images

An image the document has no file for shows as a placeholder. Give the document a `resolveImage` to fill such paths
in: the client finds complete `image("…")` strings in the input, calls it once per path, and writes the bytes it
returns into the document's files. `fetchImages` from [`@typstream/engine/images`](#typstreamengineimages) downloads
URLs from the hosts you allow. See [Images](/docs/guides/images).

## Typst packages

Documents may `#import "@preview/…"` packages from an allowlist: the `packages` of `initialize` (engine-wide) plus
those of each document (`engine.open({ packages })`, which `mountTypstream` fills from plugins' `engine.packages`).
Nothing outside the allowlist is fetched; an empty allowlist means no network. Allowed packages are fetched when a
document imports one, checked against their `integrity`, and kept in Cache Storage (`typstream-packages`) so they work
offline after the first load. A version that isn't allowed resolves to the nearest allowed one, with a warning.
Files keyed `@namespace/name:x.y.z/path` in a document's or plugin's `files` make a local package importable with no
download. [`@typstream/universe`](/docs/reference/universe) lists the packages typstream allows by default; see
[Typst packages](/docs/guides/typst-packages).

```ts
const createEngine: (options: EngineOptions) => Engine;
```

Creates the engine client and starts its worker (and, by default, a spare). Create one per page or per app and open a

#### `DocumentStatus`

```ts
type DocumentStatus = "idle" | "compiling" | "stale" | "error" | "done";
```

| Status | Meaning |
| --- | --- |
| `idle` | The artifact shows the latest input; waiting for more. |
| `compiling` | A compile is scheduled or running. |
| `stale` | Streaming, and the latest compile failed (see `failure`). The artifact is the last good one. It stays `stale` until a compile succeeds. |
| `error` | The finished document failed to compile, or the engine can't run. |
| `done` | The finished document compiled. |

#### `CompileFailure`

Why the latest compile produced no artifact. Set while the status is `stale` or `error`.

<auto-type-table path="packages/engine/src/document.ts" name="CompileFailure" />

| `reason` | Meaning |
| --- | --- |
| `diagnostics` | The source has errors (they are in `diagnostics`). |
| `timeout` | The watchdog stopped a compile that ran past its budget. |
| `crash` | The worker died during the compile. |
| `too-complex` | Repeated timeouts or crashes, or more pages than `limits.livePages`, stopped live compiling. The document compiles once more when it is finished. |
| `too-large` | The input is longer than `limits.maxLength`. It isn't healed or compiled until `set()` or `reset()` makes it shorter. |
| `engine` | The worker refused the request or couldn't start. |

### Exports

`EngineDocument.exportPdf()` and `exportHtml()` compile `exportSource()` (the healed input) in final mode with the
document's preamble and files, by the same engine as the preview. They run before compiles that are waiting, under the
final watchdog budget. Call `finish()` first to export the finished document. HTML exports have no source anchors and
are not sanitized; [`standaloneHtml`](/docs/reference/dom#standalonehtml) makes them a safe file. See
[Exports](/docs/guides/exports).

```ts
doc.finish();
const pdf = await doc.exportPdf();
const html = await doc.exportHtml({ inputs: { showAnswers: "true" } });
```

### `engineWorker`

```ts
const engineWorker: () => SpawnEngine;
```

Spawns the default engine worker: engine-wasm (Typst 0.15.1) with the base fonts (Libertinus Serif, New Computer
Modern Math, DejaVu Sans Mono), and script fonts that download the first time a document uses them. Pass it to
`createEngine` in a browser. It is written as `new Worker(new URL("./worker.js", import.meta.url), { type: "module" })`,
and the worker refers to the wasm and fonts the same way, so bundlers emit all of them as assets.

### `fromWorker`

```ts
const fromWorker: (create: () => WorkerLike) => SpawnEngine;
```

A `SpawnEngine` for Web Workers, or anything shaped like one. Use it to spawn your own worker script:

```ts
const engine = createEngine({
  spawn: fromWorker(() => new Worker(new URL("./engine.worker.ts", import.meta.url), { type: "module" })),
});
```

`create` is called once at startup and again for every replacement (watchdog, crash, recycling); each call must start
a fresh worker.

## Server API (`@typstream/engine/server`)

The worker half. Import it in a worker script of your own to load the wasm or fonts from elsewhere, replace the
fixers, or host the engine over another transport. The default worker is one line of it:

```ts title="engine.worker.ts"
import { engineWasm, serve } from "@typstream/engine/server";

serve(engineWasm({ wasm: "https://cdn.example.com/typst-0.15.1.wasm", fonts: ["/fonts/Libertinus.otf"] }));
```

Spawn it with [`fromWorker`](#fromworker). The server keeps each document's text, preamble (evaluated before the
document; diagnostics stay in document coordinates), files and inputs, and sends changed pages only. A wasm trap (a
Typst panic, or out of memory) ends the worker so the client replaces it.

### `serve`

```ts
const serve: (
  adapter: EngineAdapter,
  scope?: WorkerScope,
  options?: Pick<ServerOptions, "fixers" | "packages">,
) => EngineServer;
```

Runs the engine server in this worker, answering the client's messages with `adapter`. `scope` defaults to the
worker's global scope. `options.fixers` replaces the built-in fixers (`[]` turns them off); `options.packages`
configures Typst packages (by default the client's allowlist is used).

```ts
serve(engineWasm(), undefined, { fixers: [pendingRef, myFixer, tailCut] });
```

### `inProcess` (beta)

```ts
const inProcess: (
  createAdapter: () => EngineAdapter,
  options?: Pick<ServerOptions, "fixers" | "packages">,
) => SpawnEngine;
```

<Callout type="warn" title="Beta">
`inProcess` may change before the first stable release.
</Callout>

A `SpawnEngine` that runs the server on the calling thread, for tests and Node. Messages are structured-cloned and
delivered on later tasks, as a worker's would be, but compiles block the thread and `terminate` can't stop one that is
running, so the watchdog can't rescue a runaway document. `createAdapter` is called once per spawn.

```ts title="Node"
import { readFileSync } from "node:fs";
import { createEngine } from "@typstream/engine";
import { engineWasm, inProcess } from "@typstream/engine/server";
import { baseFonts } from "@typstream/engine-wasm/fonts";

// Node's fetch can't read files, so pass the wasm and fonts as bytes.
const wasm = readFileSync(new URL(import.meta.resolve("@typstream/engine-wasm/engine_bg.wasm")));
const fonts = baseFonts.map((url) => new Uint8Array(readFileSync(url)));
const engine = createEngine({ spawn: inProcess(() => engineWasm({ wasm, fonts })), spare: false });
```

For servers, [`@typstream/node`](/docs/reference/node) packages this up.

### Fixers

```ts
const DEFAULT_FIXERS: readonly DiagnosticFixer[]; // [pendingRef, missingImage, packageStub, hoistImport, tailCut]
const pendingRef: DiagnosticFixer;
const missingImage: DiagnosticFixer;
const packageStub: DiagnosticFixer;
const hoistImport: DiagnosticFixer;
const tailCut: DiagnosticFixer;
```

The built-in Layer 3 fixers described [above](#fixers-and-fallback), exported so a custom worker can keep some of them
next to its own. Fixers are tried by `priority` (`pendingRef` runs at 10, `missingImage` at 15, `packageStub` at 20,
`hoistImport` at 25, `tailCut`, the catch-all, at 100). Write your own as a [`DiagnosticFixer`](/docs/reference/core#diagnosticfixer).
Leaving `missingImage` out also turns off the placeholders the server stands in before the first compile.


Where typstream's runtime library is mounted in every document's files: the Typst functions fixes and fallbacks insert
(`pending-ref`, `pending-text`, `error-block`, `missing-package`), imported as `typstream` by compiles the worker
changed. A document's own file at this path replaces it, for example to restyle the placeholders. In HTML they carry
the classes `typstream-pending-ref`, `typstream-pending-text` and `typstream-error-block`.

#### `PREAMBLE_PATH`

```ts
const PREAMBLE_PATH = "<preamble>";
```

The `Diagnostic.file.path` of problems inside a document's preamble. The preamble isn't a file the document can
import; it is evaluated in front of it.

#### `fromMain`

```ts
const fromMain: (d: Diagnostic, offset: number) => Diagnostic;
```

Moves a diagnostic from `/main.typ` (preamble + document) into document coordinates, where `offset` is the length of
what precedes the document. Problems inside the preamble report it as their `file`, with the nearest call site in the
document as `span`. For adapters and custom servers.

### Re-exported types

`EngineConnection`, `EngineEvents`, `SpawnEngine`, `SpawnDefaults` and `WatchdogOptions` (what `inProcess` returns)
are the same types as the main entry's; see [`SpawnEngine`](#spawnengine).

## `@typstream/engine/websocket`

The client's transport to an engine on a server, such as [`@typstream/node`'s](/docs/guides/remote-engine). It is its
own entry point, so apps that compile in a worker don't download it (about 1 KB gzipped).

### `fromWebSocket` (beta)

```ts
const fromWebSocket: (url: string | URL | (() => string | URL), options?: WebSocketOptions) => SpawnEngine;
```

<Callout type="warn" title="Beta">
`fromWebSocket` may change before the first stable release.
</Callout>

A `SpawnEngine` over a WebSocket. Each call opens a connection, which is a session on the server with its own
documents; messages are core's [wire format](/docs/guides/remote-engine#the-wire-format). Pass a function as `url` to
compute it for every connection, to sign each one afresh, say.

```ts
import { createEngine } from "@typstream/engine";
import { fromWebSocket } from "@typstream/engine/websocket";

const engine = createEngine({ spawn: fromWebSocket("wss://typst.example.com/typst") });
```

- **Watchdog.** A compile past its budget closes the connection; the server cancels what the session had queued, and a
  new connection opens. The default budgets (`WEBSOCKET_DEFAULTS`: 10 s streaming, 30 s final and per hang probe) sit
  above the most a `@typstream/node` server takes with its default timeouts (about 4.5 s and 15 s), so the server's own
  timeout answers first and costs one compile, not the session.
- **No spare.** A spare would be a second session per page; with the server's watchdog answering first, replacements
  are rare.
- **Opening.** An attempt to open a connection that fails is retried `retries` times (4), after `retryDelayMs` (500 ms),
  doubled each time. When every attempt fails, the engine fails (an engine `failed` event), or the replacement does.
- **Dropped connections** report `lost`: the engine emits `disconnect`, opens a new connection, documents open
  themselves there, and the compile or export that was running is retried, without a watchdog strike. Three losses in
  a row with requests in flight make the next one a crash (a strike), so a request that drops the connection every time
  (larger than the server's `maxPayload`, say) stops. A connection that closes before it answers `initialize` (a server
  that refuses it) fails the engine rather than reconnecting in a loop.

## `@typstream/engine/images`

Downloads the image URLs a document names. It is its own entry point, so apps that don't show images from the web
don't download it (about 1 KB gzipped).

### `fetchImages`

```ts
const fetchImages: (options: FetchImagesOptions) => ImageResolver;
```

An `ImageResolver` for `http(s)` URLs from the hosts you allow; other paths are left to the document's files (`null`).
Pass it as a document's `resolveImage`.

```ts
import { fetchImages } from "@typstream/engine/images";

const resolveImage = fetchImages({ hosts: ["upload.wikimedia.org"] });
const doc = engine.open({ resolveImage });
```

- **Hosts** are required: `"example.org"`, `"*.example.org"` (its subdomains) or `"*"`. A URL from another host fails
  with `… isn't an allowed image host`, and nothing is fetched.
- **Requests** go without credentials or referrer. With `proxy`, the URL it returns is fetched instead, with the page's
  credentials: your server can then cache, resize, and reach hosts that don't allow cross-origin requests.
- **Content.** PNG, JPEG, GIF, WebP and SVG, recognised by their bytes, up to `maxBytes` (10 MB) and within
  `timeoutMs` (15 s). Anything else fails with the reason, which the image's diagnostic shows.
- **Caching.** Each URL is downloaded once for every document that asks, for as long as the resolver lives, so create
  one per app. A failed download is tried again by the next document that asks.

## `@typstream/engine/worker`

The default worker script: `serve(engineWasm({ fonts: baseFonts, lazyFonts: [...extraFonts, ...scriptFonts] }))`, with the fonts from
`@typstream/engine-wasm/fonts`. It has no exports; importing it starts the server in the current worker.
`engineWorker()` spawns it, so you rarely need it directly.
